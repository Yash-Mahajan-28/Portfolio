# Engineering Atlas

The new user answers supersede unresolved Phase 2 notes. This is a personal portfolio, not a collection of deep project case studies. Focus: software/backend and applied AI, with systems, research, and personality.

## Alternatives considered before UI code

1. Engineering atlas: spatially connected disciplines, navigable as chapters.
2. Annotated score: an editorial sequence borrowing structural rhythm from music.
3. Sectional instrument: exploded layers representing areas of engineering experience.

Reject the obvious centered hero, project-card grid, skills logos, and unrelated 3D backdrop. Choose the atlas because breadth is the distinguishing factual relationship. The name and positioning stay immediately readable. Five labelled, keyboard-accessible stations navigate to actual content. Node relationships reflect cross-domain work; no claim of physical space is made.

## Visual and interaction thesis

Charcoal/forest ink, warm white lettering, restrained acid green. Serif name and selected headings paired with precise sans-serif body text and monospaced annotations. Asymmetrical opening, useful 3D map, editorial timeline, compact selected-work entries, contrasting research chapter, attributed recognitions, personal music note.

The 3D map is a navigational diagram, not a simulated project, building, or scene. Selection focuses its corresponding station, displays relevant work, and provides a direct chapter link. Scroll updates the selected station. No idle particles, cursor effects, camera rides, or scroll locking. Mobile gets a vertical map and compact chapter navigation, not a scaled desktop layout. Reduced motion or unavailable WebGL gets the same semantic navigation through an HTML/SVG map.
